# Prompt 库 · 复制后补齐输入

[返回总览](../README.md) · [完整 Bot 模板](../04-templates/README.md)

下面的 Prompt 用于一次性任务，不代替长期职责或产品权限。方括号是你需要填写的内容。

## 首次任务

```text
目标：[这次要完成什么]
范围：[时间起止、时区、对象]
来源：[链接、授权工具或脱敏附件]
输出：[格式和保存位置]
允许动作：[读取/写草稿/其他已授权动作]
需要确认：[发信、发布、删除等]
完成标准：[我如何检查结果]
先检查输入与访问权限；缺失时列出阻塞，不编造。
```

## 工作前澄清

```text
先给出你理解的目标、准备使用的来源和验收方法。
只有缺失信息阻止任务时才提问；可独立完成的部分继续。
未知事实单列，建议与事实分开。
```

## 将成功流程整理为技能

```text
把这次已验收的流程整理成技能说明：触发条件、输入、工具、步骤、
输出、检查与失败处理。去掉临时日期和文件名。
用新样例验证可复用性；先给我审阅，不自动启用例行任务。
```

## Chief of Staff 派单

```text
请把这项任务分配给现有专家：[任务]。
每项写任务 ID、负责人、目标、输入、权限、截止时间/时区、产物和验收。
专家名单：[名单]。不要新建 Bot 或改变工具权限。
没有 Bot-to-Bot 能力时给出可手动转交的任务单。
收到成果后检查来源、遗漏和冲突，再汇总。
```

## 专家交接

```text
任务 ID：[ID]
提交：结果摘要、成果路径、证据来源、验收记录、未决项。
区分已执行/未执行、已验证/待核验。
不要让接收者猜测输入、账号、日期或完成状态。
```

## 检查一份成果

```text
按原任务标准检查这份成果。
列出无来源的事实、遗漏项、日期/时区错误、越权动作和资料冲突。
检查真实产物；不能访问时明确说明，不宣称检查通过。
给出可操作的修订清单，并标注是否影响交付。
```

## 调查失败

```text
暂停这项流程的新增外部写入。
说明最后成功步骤、失败步骤、可观察证据和影响范围。
分别检查权限、输入、工具、流程与产品限制。
提出一个针对原因的最小重试；不要原样无限重跑。
```
