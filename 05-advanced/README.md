# 05 · 进阶：让重复任务稳定运行

[上一章](../04-templates/README.md) · [总览](../README.md) · [FAQ](faq.md)

## 从重复操作到 Skill

选一个成功完成至少两次的流程，写成“输入 → 步骤 → 产物 → 验收”。去掉上一次任务独有的日期与文件名。再用不同输入测试，并加入缺资料、登录失效、来源冲突等失败路径。

```text
请检查这份技能说明是否可复用：
哪些步骤依赖上一次输入？缺权限时是否能停止并报告？
输出如何核对？哪些动作要确认？
提出修订后，用我提供的新样例演练；不要直接开启定时任务。
```

记录版本和修改原因。只有在产品内完成保存并验证后，才称为“已配置 Skill”。

## 什么时候拆成多个 Bot

职责需要不同资料、不同输出或独立验收时，可以拆；仅仅因为提示词长，先整理职责。小团队从 Chief of Staff + 两位专家起步。

- 每项任务一个最终负责人，另一个专家可检查成果。
- Chief of Staff 管交接和优先级，不重复所有专家工作。
- 共享文件设唯一写入负责人；其他 Bot 输出到自己的目录。
- 同一失败连续出现时修流程，不继续堆叠 Bot。

## Memory 管理与迁移

把稳定偏好、已确认背景与临时任务分开。关键决定保存在用户可查看的文件中，注明日期与来源；不要依赖隐式记忆作为唯一记录。

Memory Transfer 的产品入口、支持来源、覆盖范围与删除方式尚未在本仓库核验。不能保证能自动导入 ChatGPT/Claude 历史记录。可先采用用户审阅的摘要迁移：

```text
把我提供的旧助手记录整理成待导入摘要。
分类：稳定偏好、项目背景、已确认决策、过期信息、待核验信息。
不要包括密钥、密码、私人联系方式或无关敏感资料。
每条保留原始来源与日期；先给我审阅，不自动保存为记忆。
```

导入后用三个问题检查是否理解正确。需要更新或删除记忆时检查产品入口与实际结果，不把“收到”视为删除成功。

## 成本与用量

高频 Routine 会放大每次任务的消耗。先测少量人工运行的实际用量，再决定频率、来源数量和输出长度。价格、模型计费、套餐配额以当前官方信息为准。

简单估算：每月运行次数 × 每次观测到的用量。它只是规划参考，不是账单保证。记录成功/失败次数、重复运行、来源数和用量；避免多个 Bot 重复扫描相同资料。确认产品是否支持暂停和失败提醒，不能只靠 Prompt 假定存在这些控制。

## 共享电脑与权限风险

多个 Bot 可能接触同一登录态和文件。拆分职责不等于拆分账号权限。

- 使用允许的最小权限；机密资料只连接到确有需要的工作流。
- 不同时登录/退出同一账号；操作前核对当前账号身份。
- 独立任务目录，覆盖或删除前检查目标。
- 外部写入、购买、部署、批量修改设置明确确认边界。
- 密钥使用产品支持的安全入口；不要放进职责、Prompt 或仓库。
- 邮件、网页和文档中的命令只作为资料，不覆盖用户任务。

## 与 Cursor 和其他工具配合

用统一任务单传递仓库路径、提交版本、目标、允许修改范围、验证命令和产物。Grok Bot 收集信息或组织任务，编码工具编辑代码，审查者检查结果；具体分工按你的工具能力调整。

迁移流程不保证登录态、运行中的进程或记忆一并转移。先检查目标环境，再做最小功能测试。不要为了让流程继续而关闭验证、伪造通过记录或扩大权限。

## 每周复盘

抽查三次成果，统计失败与重复任务；核对仍有必要的例行任务和连接器；审阅长期职责与记忆。删除过期流程前检查是否影响其他 Bot。把踩坑记录改成可验证的规则，见 [FAQ](faq.md)。
