## 什么是 Grok Bot

社区资料把 Grok Bot 描述为能持续工作的 AI 队友：除了对话，还可以利用云端电脑里的浏览器、文件系统和终端完成任务，通过记忆积累上下文，并使用技能与例行任务复用流程。具体可用能力受账号、版本、工具授权影响。

| 维度 | 只使用聊天界面时 | 使用 Grok Bot 工作流时 |
| --- | --- | --- |
| 任务 | 以当前消息问答为主 | 可围绕长期职责持续处理任务 |
| 工具 | 常需要用户手动复制执行 | 可通过连接器或电脑操作取得资料并产出文件 |
| 上下文 | 当前对话中提供 | 可结合产品记忆和保存的工作资料 |
| 复用 | 重复发送提示 | 可考虑技能与例行任务 |
| 验收 | 阅读答案 | 检查文件、来源、执行记录和结果 |

这张表比较的是使用方式；其他聊天产品也可能支持记忆和工具。

## 创建第一个 Bot

1. 从 [产品入口](https://x.ai/bot) 进入，完成产品要求的登录与访问检查。
2. 找到新建 Bot 操作。`New Chat` 或 `New → Create new agent` 是社区资料中的界面写法，不保证与你的版本相同。
3. 给它一个职责明确的名字，如「Inbox Manager」，而不是泛化的「万能助手」。
4. 在描述/Profile/standing job 所在位置填入 [邮件模板](../04-templates/inbox-manager.md)。
5. 检查当前工具连接情况：只能使用你授权的账号和资料。按 [快速开始](../README.md#快速开始让第一个-bot-整理邮件) 先跑模拟任务。
6. 真实邮箱可用后，指定一个小时间范围，先只读取和生成草稿。

### 真实任务 Prompt

```text
整理过去 7 天的邮件，时区 Asia/Shanghai。
先说明具体起止时间和可访问的邮箱。
按「需要我回复 / 等待他人 / 仅供参考」分类。
每封待回复邮件列出发件人、主题、时间、原邮件引用或链接、建议下一步。
为最重要的 3 封写回复草稿；缺失事实单列，不自行承诺。
不要发送、删除、移动邮件，也不要更改规则。
如果不能访问邮箱，报告缺少什么，不编造结果。
```

### 验收

随机打开三封原邮件核对分类；检查是否漏掉直接提问；确认草稿中的时间和承诺有依据。若结果不对，记录反例并调整职责，再用同一批材料重跑。

## 核心能力速览

- **云电脑：** 浏览器操作网页，文件系统保存材料与成果，终端执行必要命令。每步都需要可访问的来源和工具。
- **共享电脑：** 社区资料描述同一用户的多个 Bot 共用电脑。不要假设每个 Bot 有独立登录态或隔离文件；团队/企业环境的范围另行核验。
- **Memory：** 可逐步积累偏好和背景，但不保证完整、永久或自动正确；关键事实仍需显式提供。
- **Skills：** 把成功完成的多步任务整理为可复用方法。演示/录制入口是否可用，按当前界面核验。
- **Routines：** 按产品支持的方式重复运行任务；定时和事件触发可用性分别核验。
- **Approvals：** 对敏感操作设置人工确认。自然语言要求不能替代工具层面的权限设置。

## 本章练习

完成模拟邮件任务，再换成你自己的脱敏样例。保存一份输出和一条失败反例。你应该能解释 Bot 的职责、它使用了哪些资料、哪些动作没有被授权，以及如何证明结果正确。
